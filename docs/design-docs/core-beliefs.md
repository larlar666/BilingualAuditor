# 项目原则与协作偏好

更新时间：2026-11-03。职责：保存稳定原则，不承载当前功能清单。来源见 [聊天回顾](../evidence/chat-review-2026-11-03.md)。

- 使用中文协作，结合实际小任务解释关键技术选择、验证方法和工具用法。用户在学习开发，有 MySQL 基础；避免一次引入过多概念。
- 每次推进一个可验收的小步骤。当前产品顺序由 [D09](../../BilingualAuditor-docs/docs/decisions.md) 决定，不以新框架或工作流替代用户目标。
- 重要产品范围由用户决定，普通实现细节采用合理默认值并记录。不要重复询问 D01～D11，也不要把建议、调研推荐或纯英文跳过翻译等默认建议写成用户决定。
- 界面先简易实现，等待用户草图再迭代；视觉与交互的改进不能替代核心行为正确性。
- 保留输入、明确失败、禁止伪造成功结果。已保存内容的离线使用与首次在线查词、设备 TTS 离线能力分别验证。
- 计划、已实现、自动检查、真机验证、人工验收、部署和发布分别记录；代码存在不能证明后三项。
- 仓库保存能恢复工作的资料，聊天保留为决定/历史来源。不要求每个 agent 重读全部聊天或 docs；先按索引找必要材料。
- 阅读路径参考 [OpenAI harness-engineering 文章](https://openai.com/index/harness-engineering/) 的短入口、专题知识与逐步深入思路；本项目不照搬文章中的产品、技术栈、自动化或自治程度。
