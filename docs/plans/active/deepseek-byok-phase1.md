# 第一阶段：Android 用户自带 DeepSeek Key 直连实施计划

日期：2026-11-16；实施更新：2026-11-17。状态：**human_acceptance_required / 代码、离线自动检查与独立评审已完成，待设备人工验收**。

用户先要求形成计划，随后明确批准本计划并要求使用 Team Loop 继续开发；第一阶段开发授权已满足，收费真实验收仍未授权。上位路线见 [云端与自带 Key 规划](deepseek-cloud-byok.md)。本轮已实现 Android 代码与离线测试；未输入真实 Key、未调用真实服务、未部署，无新增费用。

## 目标与允许范围

交付一个无需电脑代理的 Android 短文翻译版本：用户自己输入 DeepSeek 官方 API Key，手机经系统 HTTPS 直接调用官方接口；用户账户承担 API 费用。原文编辑、TXT 导入和阅读页继续沿用。

本阶段提案包含：独立直连配置、掩码 Key 输入、显式连接检查、仅本次使用/可选加密保存、替换与删除、中文/中英混合译英文、纯英文不联网、英文保护、错误与取消处理。

- 本阶段直连先限定 **1,000 Unicode 码点**，含空白/标点/emoji；超限保留全文、提示并禁止发送，不截断、不拆篇、不建议拆短。纯英文同样先做本模式长度校验。这个阶段性限制不替代通用 **10,000 码点**产品合同；长文验证单列后续任务。
- 只接 DeepSeek 官方 API，一次保存一把直连 Key；不做多供应商、自定义 Base URL、模型选择器、用户 Key 云端托管、应用账号、支付、历史或文件夹。
- 不新增云端代理，不恢复 Azure/Cloudflare；现有代理代码和账本保持不变，临时电脑/通用代理配置从高级入口保留，不与直连 Key 混用。不展示尚不可用的“应用提供服务”选项。
- 新直连界面可作为默认设置入口，但绝不自动迁移、启用或回退到其他模式；已有代理配置只有用户主动切换后才改变。旧接口字段和临时 pin 行为须回归。

## 交互与状态合同

阅读页的“翻译设置”进入配置区：默认显示“自己的 DeepSeek Key”，高级入口可选择已有代理模式。直连模式固定显示 DeepSeek 官方服务，不要求用户填网址、代理 token 或证书指纹。

首次流程：输入 Key → 可选“记住 Key”（默认关闭）→ 应用配置 → 主动检查连接 → 返回阅读页 → 点击翻译。应用配置只做本地检查，不自动访问网络；连接检查非翻译前置强制步骤，避免每次翻译多请求一次。

| 操作/状态 | 约定 |
| --- | --- |
| 输入 | 默认掩码，主动显示后可查看本次输入；禁止联想/自动纠错；不将 Key 放进可恢复 UI 状态或诊断信息 |
| 配置校验 | 去首尾空白，拒绝空值、换行/控制字符，设合理输入上界；不依赖旧代理 token 正则或假定固定前缀；有效性由官方接口确认 |
| 已有 Key | 仅显示“已配置”，不自动把保存的明文回填输入框；提供替换和删除；未修改退出不影响当前配置 |
| 仅本次使用 | 保留于当前进程，配置变更后可用于请求；进程终止后需重填，旋转不等于进程终止；不写 saved state、文件、日志、备份 |
| 记住 Key | 完成加密原子写入后才提示已保存；写入失败不显示成功，不静默落成明文或切换保存方式 |
| 关闭记住/替换 | 删除旧持久记录后再确认仅本次配置；替换原子完成，不残留可用旧记录；失败提示准确反映当前实际配置 |
| 删除 | 取消并作废当前检查/翻译，清除内存引用、密文和专用 Keystore alias，重置连接状态；失败明确提示，不假装已清除 |
| 检查中/翻译中 | 禁重复提交；支持取消。编辑原文、换 TXT、换 Key、换模式均作废旧任务；迟到成功/失败不得覆盖新状态 |
| 检查通过 | 显示“Key 验证通过”，仅代表该次模型列表接口可达且通过鉴权，不承诺余额、翻译成功或质量 |
| 翻译失败 | 保留原文和已有译文，提示未产生新译文；不把错误文本放入译文，不自动清除 Key，不自动重试/换模式 |

用户提示需包含：文段直接发送至 DeepSeek、费用由自己的账户承担、纯英文原样显示不调用模型、取消/超时可能仍产生费用。App 本地限制不能作为账户总消费硬上限；首版不展示不可靠的“剩余额度”或“精确费用”。

## 技术分工与数据

文件名为建议落点，可在实现时做局部调整，不扩成无关架构重构。

| 落点 | 变更职责 |
| --- | --- |
| `TranslationPolicy.kt` / 独立配置类型 | 增加官方直连模式与 1000 码点能力；用独立类型区分 `ProxyAccessToken` 和用户 `DeepSeekApiKey`，敏感对象 `toString` 脱敏；不强塞进现有“永不含供应商 Key”的配置合同 |
| `DeepSeekTextProtection.kt`（新增） | Kotlin 保护片段、构造提示数据、严格 JSON 解析及英文恢复；纯逻辑，供离线验证 |
| `DeepSeekTranslationClient.kt`（新增） | 官方调用与连接检查、响应限长、错误归类、取消资源释放；生产域名固定，测试注入假传输不成为 UI/生产可配置端点 |
| `TranslationClient.kt` / 客户端分发 | 最小适配官方与旧代理接口，保留旧代理 requestId 校验；官方请求用本地请求上下文关联，不要求官方回显 App UUID |
| `DeepSeekKeyStore.kt`（新增） | 私有凭证读写、加密与删除；生命周期不依赖 Activity，状态仅暴露有无/保存方式，不把明文 Key 广播到 ReaderState |
| `ReaderViewModel.kt` | 配置代次、请求快照、检查/翻译互斥及失效处理；设置加载期间明确状态，不自动翻译 |
| `MainActivity.kt` / 设置组件 | 模式选择、掩码输入、保存选择、检查、替换/删除及准确提示；阅读页动态长度说明与实际限制一致 |
| Manifest / `res/xml/` | Android 旧版 backup rules 与 Android 12+ data extraction rules 明确排除凭证与迁移；保留禁明文网络 |

继续使用现有 Kotlin/Compose/协程及 HTTPS 技术；不因本功能引入第三方模型 SDK、Python tokenizer、Room 或新依赖大升级。实际代码变动导致需新增依赖时先说明用途。

持久数据仅限版本化密文记录（版本、IV、密文/认证标签及必要非敏感保存标志与active mode），位于应用私有 no-backup 存储；使用 Android Keystore AES-GCM 密钥与唯一 IV，加密写入原子替换。alias 只服务此凭证，不触及其他未来数据。读取失败、损坏、密钥失效或恢复到新设备时显示“请重新输入 Key”，不得把密文误当 Key、反复请求或静默降级。

此方案降低静态泄漏风险，不承诺运行时明文在已受控设备上绝不可获取；Kotlin/Java 字符串清除只能释放引用，不能保证物理擦除。不读剪贴板后台内容；用户主动粘贴继续使用系统行为。

## 官方接口与翻译合同

- 连接检查：用户主动触发 `GET https://api.deepseek.com/models`，带本次 Key，不发送文段；检查状态与模型列表基本格式，并确认计划使用的模型可用，不能仅以任意 HTTP 200 判通过。该动作不调用生成接口，不做后台轮询。
- 翻译：`POST https://api.deepseek.com/chat/completions`，独立 Authorization Bearer Key。初始提案为 `deepseek-flash`、非思考、非流式、JSON object，明确 `thinking.type=disabled`；输出上限提案 4096 token。开发时复核官方字段与模型能力，参数变更需记录，不偷换模型。
- 单请求建议连接超时 15 秒、读取超时 30 秒、整体截止 60 秒；整体截止须覆盖上传/读取循环，协程取消须断开实际连接，不只丢弃回调。响应体初始硬上限 128 KiB，译文 JSON 内容上限 16 Ki 字符；超界拒绝，不能截成成功结果。这些是待实现配置，未获得真实性能证明。
- 不跟随重定向；不把 Authorization 发往其他域名；仅系统证书/hostname 校验，不借用临时电脑模式自定义 TrustManager。
- 不自动重试；同一进行中的操作只发一次。App UUID 只防本地重复/迟到结果，不宣称 DeepSeek 支持该 UUID 幂等，超时后手动重试仍可能再次计费。
- 401/403、余额不足（按官方明确错误）、429、5xx、网络、TLS、超时、响应格式/截断、英文保护失败分别映射固定文案；不直接显示原始上游 body/异常，不仅凭 403 断言余额不足。
- 结果必须符合选定协议、仅一个有效选择、正常完成、无工具调用/非预期 reasoning，`content` 严格解析为唯一字符串字段 `translation`；截断或畸形结果拒绝显示。usage 如使用必须验证整数与合理范围；只作当前调用 token 展示候选，首版不做价格结算或复用旧每次 ¥0.15 证明。

保护算法复用现有 `phone-text.mjs` / `trial.mjs` 的语义而非依赖旧四固定样本门禁：

1. 按 Unicode 码点校验非空、长度及有效文本；不支持的字母脚本清楚提示，不把所有无汉字内容当纯英文。
2. 识别含 Latin 的非中文片段，保护内部拼写、大小写、空格、URL 和字面标签；中文标点留在可翻译上下文。边界空白与受保护内容区分，不能整篇 trim/格式化后冒充原样保留。
3. 拒绝与保护 marker/特殊模板标记冲突的输入；固定 system 指令，将原文作为 JSON 数据。恶意指令样本要验证，但不声称提示词提供绝对注入防护。
4. 每个 marker 必须准确出现一次，缺失、重复、未知或畸形 marker 均拒绝；恢复后不得残留 marker 或汉字，不自动纠正原英文。
5. 自然度、混合标点和片段之间语序仍需人工评价；不能由 marker 全部恢复推导译文质量合格。

Kotlin 与 JS 的 Unicode/正则细节可能不同；先整理共用合成样本及预期保护/恢复结果，逐项核对。发现现有语义缺陷时记录差异和影响，不顺手重写旧试验或将旧证据套给新客户端。

## 验证矩阵与人工验收

自动检查覆盖有实际风险的合同，不为每个界面标签增加镜像测试：

- 文本：0/1000/1001 码点、补充平面汉字、emoji、纯英文零网络、unsupported letters；英文精确保留及无效模型输出拒绝。
- 请求：有效/无效 Key、余额错误、429、服务异常、重定向目标未收到 Key、坏 JSON、超大 body、读取阻塞、取消和截止；确认无自动重发。
- 状态：检查与翻译互斥；编辑/换文件/换 Key/换模式/删除使旧结果失效；取消后新请求可正常开始；失败保留原文。
- 存储：加密回读、不同 IV、原子替换失败、密文损坏、alias 失效、关闭保存/删除、旧版本记录；Key 不进普通设置、日志、异常、saved state 或备份规则。
- 回归：现有 TXT 流程、通用代理、热点 pin 与 health 不因新模式改变。

命令按 [质量入口](../../QUALITY_SCORE.md) 分别运行 `:app:assembleDebug`、`:app:testDebugUnitTest`、`:app:lintDebug`，记录提交/工作区版本、APK 哈希、结果与残留警告；设备测试不能由 JVM 测试替代。Keystore、进程终止恢复和备份/迁移排除优先用设备或仪器验证，不能以 XML 存在宣称所有设备行为通过。

人工清单：

1. 电脑关闭，手机 Wi-Fi/移动网络下可配置直连，连接检查无生成请求；代理设置不出现用户 Key。
2. 仅本次模式进程终止后不保留 Key；最后主动应用为直连且记住模式重启恢复为已配置；若最后应用代理/清除代理，重启保留该代理模式且未配置，不自动启用保留Key；无模式元数据的旧Key首次需主动应用；取消勾选/替换/删除后行为正确，关闭设置未应用不修改原配置。
3. 至少用纯中文、中英混合、故意错误英文和 URL/字面标签四类合成样本对照；纯英文额外离线确认不请求生成。
4. 1001 码点禁止发送、全文保留，无自动截断/拆篇；断网、超时、取消后提示不承诺零扣费。
5. 翻译时编辑或切换配置，旧结果不覆盖；连续点击不重复外发。

真实付费验收预算**尚未授权**。建议后续独立最多四次短合成生成请求、总费用上限提案 ¥1、首错停止、无自动重试；开始前须核对账户币种、当前单次保守上界和实现可执行的计数/持久预留方案，未证明上界则缩小样本或不执行。它不是对公开 BYOK 功能承诺硬预算，更不是旧固定四样本/热点账本的重新初始化。开发与假上游测试可先全部完成，收费测试留作明确预算后的步骤。
