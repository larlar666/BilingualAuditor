## DIF-001：授权成功不等于连接长期可用

- **发现与核对**：11-08 至 11-12 的排查已有专题记录；本条于 2026-11-12 整理。
- **现象与影响**：浏览器加载慢、回到控制台首页、回调超时或 CLI 认证失败，阻挡部署与后续验证。
- **已知事实**：曾使用十分钟本机等待辅助工具完成授权；11-12 的关闭态部署未取得成功证据。控制台登录、本机代理服务运行和命令行认证有效是不同事实。
- **根因边界**：页面加载与系统代理配置差异是调查线索，不足以解释全部后续认证失败。
- **经验与下一步**：先核实际登录和目标生产元数据；不要循环打开旧链接或用历史成功代替本轮证据。Azure 已按用户聊天指示暂停；DeepSeek 本轮已批准先走本机直连，绕开云端授权前置，但不据此认定云端连接问题已解决。执行阶段见[本机记录](evidence/deepseek-local-trial.md)。

## DIF-002：测试环境与生产运行时存在差异

- **发现与核对**：2026-11-11 至 11-12 的本地排查，详见专题。
- **已确认根因**：Node 接受的 `redirect: "error"` 在固定 workerd 运行时构造请求时抛错，旧假上游测试未捕捉该兼容性缺陷。
- **处理与验证**：改用 `manual`，在解析正文前拒绝 300–399；Node 18/18 和真实 workerd 假上游检查通过，跳转目标调用为零。
- **状态边界**：这是本地修复证据，不是成功部署或 Azure 翻译成功证据。
- **经验与下一步**：涉及平台特有 API 的关键路径，应增加目标运行时检查；未来恢复部署时保留不跟随重定向的安全合同。

## DIF-003：直连验证必须核对凭证用途

- **来源与日期**：2026-11-12 主聊天报告，不是本侧重新执行的验证。
- **现象与影响**：一次本机直连报告 HTTP 401，用户随后表示不确定输入 Key 的来源，并选择先暂停 Azure、继续 DeepSeek。
- **未知项**：服务 Key 来源、资源绑定及失败的具体原因仍未确认；401 不等于已经证明某个具体 Key 无效。
- **处理与证据**：本轮已将 Leader 提供的安全结果和人工暂停回写[专题证据](evidence/translation-live-configuration-audit.md#2026-11-12-并行试验与本机直连)，[Azure 计划](plans/active/translation-integration.md)明确暂停；不是本轮重新执行直连。
- **经验与下一步**：区分 Azure 服务 Key 与应用个人访问凭证；仅由本人在本机掩码窗口输入，不记录值或密钥页截图。暂停不是解决，恢复前先确认执行范围及待核凭证来源。

## DIF-004：费用估算不能冒充计量证明

- **发现与核对**：2026-11-12，详细资产、计数和有效期归预算证据主落点。
- **现象与影响**：通用字数换算及旧分词包不足以证明当前托管模型完整消息的计费输入，影响 ¥1 试验的启用判断。
- **处理与边界**：采用固定官方模型提交、编码参考和完整请求哈希做离线计数；既有 Worker/D1 方案的独立离线复核已通过，范围见计划。本机模式及输出帧修复于 11-13 取得独立 preGate；随后四个真实固定样本全部通过，返回 usage 与离线 response-format 变体计数一致，详见[本机主证据](evidence/deepseek-local-trial.md#2026-11-13-四固定样本真实结果)。本轮原账本四次认领已满，不重置；本地证明仍不是托管账单的绝对保证，也不能推广到通用长文。
- **经验与下一步**：保留固定总预算、原子预留及过期拒绝；用户已确认人民币账户并批准本机持久账本及排他归属；本轮 usage 核对已完成，平台账单未读取；缺账本拒绝、初始化不可重置和本机／远端不能双领仍是后续约束。四次认领已用完，后续真实请求必须另定范围与预算，不能因 proof 续新重置本轮额度。

## DIF-005：文档阶段漂移

- **2026-11-14 入口复核**：根 `README.md` 仍称在线翻译未接入、把旧目录当作文档总入口，并要求更新历史进度；与 `product/current-state.md` 和 `PLANS.md` 的 owner 分工不符。当前维护规则没有明确列出根 README 的受影响摘要检查；包内 docs-review 的 scanner / apply validator 仅覆盖单个 docs root，扫描 `docs/` 不包含根 README 和旧文档目录。这是已核实的覆盖缺口，不能据此断言某次历史执行的具体漏改过程。
- **本次处理与限制**：补充包内 docs-review 的入口语义检查、覆盖范围披露及范围外冲突处理；未运行全量 docs-review，未修改个人 skill 安装目录、根 README 或 scanner / validator。普通每轮维护仍需在项目规则中落实受影响入口检查，单改显式触发的 skill 不会自动同步未来开发轮次。

- **影响**：新会话可能重复授权、排查已定位问题，或把历史恢复误当当前状态。
- **处理与验证**：在本轮续接范围内，将 Azure 401/来源未知/人工暂停归回专题证据和计划；将 DeepSeek 作为当前主线并链接其预算证据，移除交接中仍引导 Azure 调查的旧入口。本轮静态检查结果由执行者报告，不代表线上验证或全量事实对账。

## DIF-006：跨进程检查必须验证真实输出帧

- **发现／核对日期**：2026-11-13；处理范围为本机掩码启动器的 Node 预检，不涉及 Cloudflare 授权或模型请求。
- **已确认根因**：当前 PowerShell/.NET 的 `$errorDrain.GetAwaiter().GetResult()` 将 `VoidTaskResult` 写入成功管道；检查函数同时返回它和正常字典，调用方得到数组后拒绝。纯检查帧的初始化标志两种值均通过，不能归因于预算或证明损坏。
- **处理与验证阶段**：最小抑制输出修复已完成，原源码新增回归失败、修后 parser／SelfTest 通过，真实 Node check-existing／check-init 均验证恰好一个字典；已有账本普通检查保持单字典及零认领。随后 delta evaluator 的独立 parser／SelfTest 与单字典检查通过；随后复用原账本完成四个固定样本，均 HTTP 200；本轮四次额度用完，不再请求或重置。原账本始终保留，最终四次认领已满；没有因修复重建账本或释放额度。
- **经验／下一步**：PowerShell 跨进程包装器应显式消耗非业务返回值；合成帧自测应保留真实子进程输出形状回归。后续继续沿已有账本，不重复初始化、不重置额度；输出帧范围的缓解不代表模型或手机验收通过。详细结果只维护于[本机主证据](evidence/deepseek-local-trial.md#2026-11-13-离线评审与首次启动)。
